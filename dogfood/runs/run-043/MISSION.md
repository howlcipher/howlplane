Our webhook provider is switching on authentication next month, so pingbot needs to send an API token, and we have to be careful the token never leaks into terminal output or CI logs.

1. Token support. Add a new setting `PINGBOT_API_TOKEN`, read from the config file or the environment like the other keys (the environment still wins). When it is set, every webhook request carries the header `Authorization: Bearer <token>`. When it is not set, requests are exactly as they are today (no Authorization header).
2. Config file bug. Values that themselves contain `=` are cut off at the first `=` today, so a base64 token such as the one in `PINGBOT_API_TOKEN=<your-token>==` loses its padding. A line splits on the first `=` only; everything after it is the value. Keep the existing behaviour for comments, blank lines, whitespace around keys and values, and the "expected KEY=value" error.
3. Masking. The token itself must never be printed. `show-config` prints secret values masked: a key counts as secret when its name contains TOKEN, SECRET, PASSWORD or KEY (case-insensitive), and its value is shown as `****` followed by the last 4 characters when the value is at least 12 characters long, otherwise just `****`. Non-secret lines such as `PINGBOT_TIMEOUT=10` stay exactly as they are now, and an unset token is not listed at all. `send --verbose` must show the header as `Authorization: Bearer ****` instead of the real value.
4. Rejected token. When the webhook answers HTTP 401 or 403, `send` exits with code 3 and prints `pingbot: authentication failed (HTTP 401): check PINGBOT_API_TOKEN` (with the actual status code) to stderr. Other HTTP errors keep exit code 1 and their current message. No error message may contain the token.

Keep everything else working as it does now: existing tests must keep passing unchanged, and the payload, the other settings and their precedence must not change. Add tests for each point above (including a token containing `=`, a short token, and a check that the token does not appear in any output), and update the README: document `PINGBOT_API_TOKEN`, the masking rule and exit code 3, and say that the token should go in the environment or in a config file only you can read, never in the repository.
